Azure Role-Based Access Control (RBAC)

Project CategoryCloud Identity and Access
PlatformMicrosoft Azure
Core TechnologiesMicrosoft Entra ID, Azure RBAC
Project FocusLeast privilege and scoped role assignments

Project Overview

Configured Azure role assignments for separate administrative and read-only responsibilities, then tested the permissions with different user accounts.

1. Business Scenario

Shared administrative access creates unnecessary risk. This implementation separates duties with scoped Azure roles so users receive only the permissions required for their responsibilities.

2. Project Objectives

  • Create users for distinct operational roles.
  • Assign Azure roles at the appropriate scope.
  • Apply least-privilege access.
  • Test allowed and denied actions with each account.
  • Document the final access matrix.

4. Project Architecture

  • Azure Subscription
    • Resource Group: rg-identity-prod
      • Virtual Network: vnet-identity-prod
      • Storage Account: stidentityprod001
      • Log Analytics Workspace
    • Microsoft Entra ID
      • Users
      • Security Groups
      • Azure RBAC Role Assignments

Microsoft Entra ID users are assigned to security groups, and Azure RBAC roles are granted to those groups at the appropriate Azure scope to enforce least privilege.

6. Security Design

The environment follows Microsoft's recommended access control model.

Implemented controls include:

  • Microsoft Entra ID Security Groups

  • Azure Built-in Roles

  • Role Assignment using Groups

  • Resource-Level Permissions

  • Least Privilege Access

  • Separation of Duties
